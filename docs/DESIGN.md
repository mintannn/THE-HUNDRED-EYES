## 体験の軸

「大きな声」と「たくさんの人」は違う。

暗い空間に100の目が浮かび、中央の投稿を見ている。最初は少数の批判、あるいは称賛へ注意が集まり、他の人たちは暗闇に沈む。自分の投稿がゆっくり小さくなり、声も少し遠のく。その余白に「現実へ」が浮かぶ。触れると、同じ人たちを見渡せる距離へ広がり、75〜83人の無関心と小さな好意が見えてくる。

誰かの反応が変わるわけではない。変わるのは、見る側の距離と注意。ポストも3D空間も同じまま、怖さと現実の落差を体験する。

## 体験の時間

1. 入力の間、100の目が独立して瞬く。中央に語り手の見出しは置かない。
2. 投稿すると、深さの異なる薄い露光が約3.8秒だけ空間をかすめる。手前から奥へまばたきと小さな画面の反射が伝わり、少数の目に注意が集まる。同時に投稿欄は約8.6秒かけて奥へ遠ざかる。批判側は赤い目とわずかな震え、称賛側は金色の目。心の声は少し遅れて現れ、残像は薄い一層だけ。光の糸と粒子も控えめに置く。
3. 約6.2秒後、まだ投稿が遠ざかる途中で **「現実へ」** が約2.8秒かけて浮かぶ。枠や矢印を持たない淡い筆文字。ポインターやキーボードのフォーカスを重ねると、文字が少し明るくなり、周囲の声・光・音がもう一段静まる。タップ／クリック／Enterで先へ進む。時間だけで多数派を開示することはない。
4. 押した文字がその場でほどけ、まぶたが浅く降りる。約4.8秒かけて投稿はもう少し奥へ、視野は広くなる。投稿欄は元の大きさへ戻らず、同じ空間に小さく残る。称賛した人も批判した人も、ID・感情・人数は変わらない。
5. 灰色の多数は視線を外す。ひと呼吸遅れて、声の小さなひとりが少しだけ近づき、こちらを見る。「好き。」「あとで読む。」という断片と100人の比率が現れる。音を有効にしていれば、静けさに一音だけが残る。
6. 開示後、操作せずに8.5秒眺めていると、約5〜6秒かけて数字・他人の言葉・投稿欄の輪郭が薄れる。入力した文章は同じ位置に残る。多くの目は暗闇へ馴染み、光の軌道と粒子も遠ざかる。
7. その静けさの中で、ひとりがもう一度だけこちらを見る。瞳に小さな四角い光が残る。その人もやがて視線を外す。称賛・批判のどちらもこの時間へ戻り、終幕や結論の文字を出さず、独立したまばたきと空間が続く。

ポインターを動かす、タップする、キーを押すと、輪郭や数字の表示は約0.8秒で戻る。投稿の距離は保つ。その入力は通常の操作としても届く。パラメータや一覧を読んでいる間、動きを停止している間は余韻へ進まない。非表示タブから戻ったときも表示と待ち時間を戻す。動きを減らす設定では、投稿の縮小・ズーム・残響・露光・自動で薄れる演出を省き、ボタンによる二段階の体験は残す。「書き直す」で投稿欄が手前の元の大きさへ戻る。

## 操作

- 140文字以内で入力し、「ポストする」。日本語の変換中を除き、⌘ / Ctrl + Enterでも投稿できる。
- 3つの例文は日常・よろこび・挑発。「よろこび」は称賛が前面に出る。日常と挑発は批判が前面に出る。例文を選ぶだけでは投稿しない。
- ポスト欄はXを想起するアバター、宛先、返信範囲、白い丸ボタン。青は鈍い青灰色に抑える。メディア用アイコンは演出上の装飾で、投稿するのは文章だけ。投稿後の反応は小さな文字と数字になり、開示後に現れる。
- 投稿後も同じ欄に文章が残る。投稿欄だけを奥へ動かし、「現実へ」は手前の操作できる位置に置く。スマホでは縮小を控えめにし、書き直すボタンのタップ範囲を広げる。「書き直す」で元の大きさへ戻って編集する。
- 投稿欄が小さくなって空いた場所からも、その奥の目を直接選べる。「現実へ」の操作範囲は、前面の目の言葉と重ならない位置に置く。
- 目をクリック／タップすると、透明なパラメータが目の近くに浮かぶ。縁や反射線を出さず、外へ薄く消える曇りを文字の背後にだけ置く。態度・直感・6種類の感情・声の大きさを表示する。円形のホバー枠はなく、わずかな光と番号で対象を示す。
- パラメータは出現位置に留まり、×・Escape・外側のタップで閉じる。キーボードではフォーカスを元の目に戻す。
- 背景をドラッグすると視点が動く。PCではポインターに対しても奥行きの異なる視差が生じる。
- 「100人の内側を見る」で、全員の定義文を公開する。一覧は画面内の独立した領域をスクロールし、×は常に同じ位置に残る。ホイール・タッチ・Home / Endに対応する。
- 環境音は初期状態ではオフ。批判では小さくうなり、称賛では低い和音が薄く広がる。投稿が遠ざかり、「現実へ」が現れる頃には音量も下がる。ボタンへのフォーカスでさらに静まり、開示後には432Hzの小さな一音。余韻では残っていた低音も消えていく。すべて端末内で合成する。
- 動きを止める操作、OSの「視差効果を減らす」、キーボード操作、WebGL非対応時の軽量表示に対応する。

## 3つの演出

| 投稿の文脈 | 無関心 | いいね | 有益 | 反発 | 拒絶 | 羨望 | 空間 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | --- |
| 日常 | 83 | 5 | 3 | 4 | 3 | 2 | 3人の大きな声、2人の冷笑、少しの火の粉 |
| よろこび | 75 | 12 | 5 | 4 | 2 | 2 | 共感した12人のうち3人が大きく称賛。批判3人・冷笑2人は周辺へ |
| 挑発 | 78 | 4 | 3 | 8 | 5 | 2 | 4人の大きな声、2人の冷笑、強い火の粉 |

この割合は**演出用の固定値**。文章の特徴で文脈を選び、文字列のハッシュとペルソナの態度で各人へ割り当てる。同じ文章なら同じ反応になる。感情とは別に `delivery`（無言・小さな反応・大きな批判・冷笑・大きな称賛）を持つ。称賛者は共感した人から選び、静かに共感する人を必ず別に残す。`loudCount` は大きな批判と称賛の合計。実在する100人の反応、世論、Jevの実測値ではない。内心の短文も事前に書いた演出用の文であり、モデルの説明・推論過程ではない。

`spotlight` は、どの声が大きく見えるかを選ぶ演出用の軸。現段階では「よろこび」の例文や完成・感謝などの語を含む文を称賛側に振り分ける仮のルールで、現実の炎上や人気を予測するロジックではない。将来はこの分岐だけを差し替えられる。開示ボタンは見せ方を変え、`Observation` を再生成しない。

## 見た目

- 黒を基調とした、緑と灰色がわずかに残る暗い空間。
- 4層の奥行きに分布する100の目。手前は大きく、奥は小さく暗い。
- Three.jsの透視投影と湾曲した面に、GLSLでまぶた・白目・虹彩の放射模様・瞳孔・反射を描画する。
- 虹彩の大きさ、開き、色、傾き、瞬きの周期は個体ごとに異なる。
- 投稿直後に同心円は出さない。ノイズで縁を崩した5枚の薄い光を異なる奥行きに置き、短い露光として重ねる。色は銀灰色を中心に、ごく薄く投稿側の色を含める。瞳の反射は角膜の中だけに描く。
- 粒子と薄い軌道線で奥行きを補助。前半は批判する目が拡大し、他の目は暗くなる。開示後はカメラと目の距離、透明度を補間し、同じシーンを連続して見せる。
- 前面の声は、静かな人との相対的な距離で表現する。文字・目の拡大・揺れを抑え、文字の残像は繰り返さない。72個の薄い粒子と4本の細い糸が数人の周囲にだけ残る。開示後も気持ちは残り、表示の大きさが他の人と同程度に戻る。
- 投稿欄はCSSの透視投影で遠ざかる。PCでは元の幅の約65%、開示後は約60%へ。スマホでは約77%、開示後は約74%に留める。開示ボタンは60px以上の高さを保ち、投稿と一緒には縮小しない。
- 開示時は一度だけまぶたが降り、周辺が薄暗くなってほどける。2.4秒後から小さな好意が現れ、約4.8秒で視線と瞳の反射がこちらへ戻る。動きを止めた場合と動きを減らす設定では静止表示になる。
- 操作が途切れたときの余韻は別画面にせず、同じ100人の透明度・視線・光を連続的に変える。投稿欄の表面だけを薄くし、文章を空間に残す。最後の視線も永続させず、約11秒で再び外れていく。反応データ・人数は変えない。
- 空間にはハートやリポストのバッジを浮かべず、短い心の声だけを置く。ポップアップのパラメータは銀灰色を基調にし、主な感情だけに淡く色を差す。
- 見出しと反応語は墨のかすれを持つ「Yuji Boku」。説明文を減らし、本文はX風のサンセリフ体で読みやすくする。フォントはアプリから配信し、ブラウザが必要な文字のファイルだけを取得する。
- モバイルでは投稿欄の余白・目の大きさ・描画解像度・詳細表示を調整する。

## 起動・検証

```bash
npm ci
npm run dev
# 他のプロジェクトが3000を使用中なら、表示されたポートを開く

npm run lint
npm run build
npx playwright install chromium webkit
npm run test:e2e
```

ブラウザテストは `localhost:3001` を使い、そこに既存の開発サーバーがなければ起動する。体験はPCとiPhone相当のChromium画面、一覧のスクロールはWebKitでも検証する。投稿が時間とともに小さくなること、開示ボタンの操作範囲、フォーカス時の静まり、押す前には多数派を開示しないこと、開示しても100人のID・感情が変わらないことを確認する。余韻からの復帰、再編集で元の大きさへ戻ること、背景が動き続けるパラメータ、動きを減らす設定、すべての例文で75人以上が無関心であることも検証する。テスト結果と画面キャプチャは、Git対象外の `test-results/` に出力する。

## Jevへの接続点

現状の入力はクライアント内だけで処理される。外部へ投稿・送信しない。APIキーは不要。

Jevの実判定を作品の出来事に使う次の演出案は、[JEV-ART-DIRECTION.md](./JEV-ART-DIRECTION.md)に整理している。こちらは未実装の検討案。

接続時は `observe()` の呼び出しをサーバーAPIへのリクエストに置き換え、`Reading[]` を返す。反応の人数は実レスポンスから数え、固定割合は使用しない。声の大きさ・拡散範囲は感情確率とは別の作者が設計する軸であり、Jevのconfidenceと混同しない。

ブラウザ上の描画・入力・アニメーションを分離してあるため、API待機や失敗の表示を追加しても3D空間を作り直す必要はない。
