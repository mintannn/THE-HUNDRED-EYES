# 衆目 — Jevを作品の出来事にする

2026-09-22の構想記録。同じ100人での書き直し、独立した4軸、最初の言葉の残像を実装した。人物定義が同じ目の位置に現れる終幕と最後の一行を追加し、「現実へ」は「遠くへ」に変更した。現行仕様は [REVISION-EXPERIENCE.md](./REVISION-EXPERIENCE.md) と [ARTWORK-FINISH.md](./ARTWORK-FINISH.md)。Jev接続口も実装済みだが、この環境にはAPIキーがなく、実応答による演出品質は未検証。以下は構想時点の記録。

## 公式仕様で確認した前提

- Jevは、同じstateに対する複数の問いを独立・並列に評価し、型付きの結果を返す。Choice・Score・Noulを同じ呼び出しに含められる。[1]
- Scoreは、作者が文章で定義した段階に沿う判定を返す。複数の側面は別の問いに分ける設計が推奨されている。[2]
- Choice／Scoreの確率分布とconfidenceはモデルの判定の不確かさに関する情報。confidenceを「好きの強さ」「人の心を読めた確率」に置き換えない。[2][3]
- これらはモデルの仕組みについての説明であり、架空のペルソナの反応が実在する人間を正しく予測する保証にはならない。

「他のモデルでは原理的に不可能」ではなく、Jevの小さな判定・並列性・型付き結果を、作品の時間と動きに直接使う。生成された長い台詞を中心に据えない。

## 核にしたい体験 — 一文字、消すたびに

他人の反応を見る作品から、その反応を見た自分が言葉を変えてしまう作品へ。

### 1. 言葉が届く

最初の投稿に対して100の目が判定する。少数の目に注意が集まり、投稿が遠ざかる。現在の「現実へ」を見つける流れを入口に残す。

判定は一人につき「関心」「好意」「不快」「表に出したさ」などを別々に持たせる。好意と沈黙、不快と無関心の近さ、気持ちの強さと声の大きさの食い違いを残す。

これは人間の感情の実測ではない。100の定義と問いで作る、作者のモデルである。

### 2. 見られたあと、書き直す

「書き直す」で同じ100人を保ったまま編集できる。一語を変えたとき、判定が変わった目だけが動く。静止している目も、それ自体が反応になる。

たとえば「今日はもう頑張れない」を「今日も頑張ります」に書き直す。批判が静まることもあれば、最初の言葉へ好意を持っていた目まで離れることもある。これは狙いたい分岐の例であり、Jevで確認した結果ではない。

その分岐を必ず起こす脚本にはしない。変化しない場合や、予想と逆の変化も作品に残す。入力を消すこと、元に戻すこと、変えずに出すことのどれにも点数や正解を付けない。

### 3. 元の言葉の残像

最初の投稿を好意的に受け取り、書き直した投稿では関心が下がった目が実際にあれば、その目にだけ、最初の文章の光が一瞬戻る。

説明の台詞は出さない。自分が書いて消した言葉が、自分以外の場所にまだ残っていた、という発見を狙う。

その目もやがて視線を外す。最後の一人に永久に肯定される終わりにはしない。世界は続き、元の文を選ぶかどうかは来場者に返す。

該当する目がいなければ、誰かが好いていたことを捏造しない。変化のない静けさにも終わり方を用意する。

## 驚きと寂しさをどこに置くか

| 狙う感覚 | 出来事 |
| --- | --- |
| 驚き | 同じ100人なのに、たった一語の変更で一部の目だけが動く |
| 違和感 | 強く好いている人が黙り、強く嫌っているわけではない人の声が目立つことがある |
| 寂しさ | 周囲の反応を整えるうちに、最初にこちらを見ていた目まで離れることがある |
| 余韻 | 消した自分の言葉だけが、ひとりの瞳に短く残る |
| 問い | 自分は何を伝えたかったのか。誰の反応に合わせて直したのか |

## もう一層の余韻 — 百人の奥の、ひとり

終盤に希望する人が「百の内側」を覗くと、100人の輪郭が作者の書いた定義と判断軸であると分かる。

「世間だと思っていたものは、ひとりが作った100のものさしだった」という読み方を残す。中央に説明文を出して答え合わせはしない。現在の定義公開を、この層へつなげる。

## 先に試す小さな検証

1. 代表的な少数のペルソナと、語調だけを変えた投稿の組でJevの実際の差分を見る。
2. 一つのChoiceの確率を6種類の感情量として扱わず、必要な側面を独立したScore等へ分ける。人柄・声の届く範囲は作者の設計として区別する。
3. 同じ入力と同じ定義の結果をセッション内で再利用し、再呼び出しの揺れを「一文字の効果」に見せない。新しい入力の不確かな変化も大げさに強調しない。
4. 差分が見えることを確認してから100人へ増やし、更新間隔・応答時間・費用を実測する。公式の並列性の説明を、100人分の遅延保証として扱わない。
5. 固定の「無関心75人」等をライブ判定へ置き換える。分布が予定した結論から外れても上書きしない。

新しい演出には、投稿と同じくJevへの接続・実応答の検証が必要。今回の検討ではAPI呼び出しや入力の外部送信は行っていない。
